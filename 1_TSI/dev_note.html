🚦 신호개방정보 웹 애플리케이션 개발 노트

본 문서는 UTIC(경찰청) 및 서울시 T-Data 신호개방정보를 연동하는 웹 애플리케이션의 개발 상태, 임시 적용 사항, 그리고 상용 배포(Production) 전 반드시 복구/수정해야 할 사항을 기록하기 위해 작성되었습니다.

최종 업데이트: 2026년 5월 25일

1. 앱 주요 기능 (Original Features)

기능 개요
  • 통합 지도 표출: Leaflet 기반으로 구글 위성지도 및 다크 테마 지도를 사용해 전국 교차로 위치 마커 표시.
  • UTIC 실시간 연동: 경찰청 UTIC API를 통해 교차로의 TOD/수동 제어 상태, 남은 시간, 현시(Phase) 정보 등을 실시간 모니터링.
  • 서울시 T-Data 연동: 서울시 V2X 실시간 신호 API와 교차로 마스터 데이터를 매핑하여 서울 시내 교차로 상태 확인.
  • 듀얼 모니터링: 두 개의 교차로를 동시에 선택하여 하단 플로팅 패널에서 양쪽 신호 상태를 비교 모니터링.
  • 상세 정보 창 (SigMap 등): 교차로 클릭 시 A링/B링 방향별 신호 상태, 보행자 신호 상태, 잔여 시간 등을 시각적으로 표시.

2. 현재 개발 상태 및 임시 변경 사항 (Temporary Changes)

임시 적용 사항

브라우저 보안(CORS) 문제 및 테스트 편의성을 위해 현재 코드상에 아래와 같은 임시 조치들이 적용되어 있습니다.

A. 서울시 API (Seoul T-Data) Mock 연동

  • 사유: 브라우저에서 직접 서울시 API 호출 시 발생하는 CORS 에러 방지 및 잦은 API 호출로 인한 일일 한도 초과 방지.
  • 상태: app.js 내의 proxyUrl이 실제 API 주소가 아닌 'js/seoul_spat_mock.json'(가짜 데이터)를 바라보고 있습니다.
  • 영향: 연결 상태는 '정상'으로 나오나, 실제 교차로 ID와 일치하는 데이터가 없어 대부분 '미수신'으로 카운트됩니다.

B. UTIC API 로컬 프록시 사용

  • 사유: UTIC API 역시 CORS 제한이 있어 로컬 환경에서 테스트하기 위함.
  • 상태: useProxy: true 설정으로 인해 http://127.0.0.1:3001/ 로컬 프록시 서버를 통해 통신하고 있습니다.
  • 영향: 로컬 프록시 서버(node.js 등)가 켜져 있지 않거나, 실제 웹 호스팅 서버에 배포 시 통신이 불가능합니다.

C. 초기 지도 배경 (Google 위성지도)

  • 상태: 교차로와 정지선 확인의 편의성을 위해 앱 구동 시 기본 지도가 '지명 없는 구글 위성지도'로 설정되어 있습니다. (줌 레벨 19.5 -> 18 조정 완료)

3. 운영 배포 시 원상복구 및 조치 사항 (Production To-Do)

배포 전 필수 확인

호스팅 서버에 업로드하여 실제 서비스를 오픈하기 전, 다음 사항들을 반드시 원래대로 돌려놓거나 서버 환경에 맞게 수정해야 합니다.

핵심 과제: 호스팅 서버에 리버스 프록시(Reverse Proxy) 구축
CORS 우회를 위해 로컬(127.0.0.1:3001)에서 사용하던 방식을 버리고, 실제 호스팅 서버(PHP, Node.js, Nginx 등)에 API 요청을 대신해 주는 프록시 스크립트를 세팅해야 합니다.
  • 서울시 실시간 API URL 복구:
    app.js 내 startSeoulSpatPolling() 함수에서 proxyUrl = 'js/seoul_spat_mock.json'; 부분을 주석 처리(또는 삭제)하고, 호스팅 서버에 세팅한 프록시 주소(또는 실제 API 주소)로 변경해야 합니다.
  • UTIC API 프록시 경로 수정:
    app.js 상단의 proxyBase 변수값을 http://127.0.0.1:3001/?url=에서 실제 호스팅 서버의 프록시 URL로 변경해야 합니다.
  • API 호출 주기(Polling) 최적화:
    현재 테스트용으로 짧게 설정된 실시간 업데이트(setInterval) 주기를 점검해야 합니다. 특히 지역 전체를 조회하는 경우 주기가 너무 짧으면 API 일일 허용량(Quota)이 순식간에 고갈됩니다. 상용 서비스 시 백엔드 서버에서 1회 수집 후 클라이언트(웹)로 뿌려주는 구조를 권장합니다.
  • API Key 점검:
    코드에 하드코딩된 UTIC 및 서울시 API Key가 본인의 운영용 Key가 맞는지 확인하고, 외부 노출에 주의하십시오. (운영 서버의 환경 변수로 숨기는 것이 좋습니다.)
