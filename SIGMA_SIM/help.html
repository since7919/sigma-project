SIGMA 시뮬레이터 도움말

1. 신호 시뮬레이터 기본 기능 및 데이터 연결 메커니즘 (Data Pipeline)

시뮬레이터는 시간계획(TOD) → 일계획(Day Plan) → 시그널맵(Signal Map) → 등화 연산(calc) → 화면 표출(Rendering)의 5단계 파이프라인을 통해 방향별 화살표와 신호등에 실시간 녹색불을 켜주는 핵심 관제 엔진입니다.

신호 데이터 제어 흐름도 (Data Control Flowchart)

flowchart TD
    A["시간계획 (TOD / Schedules)
현재 시각(t) 기준 운영 플랜 번호 결정"] --> B["일계획 (Day Plans / Splits)
현시별 녹색·스플릿 초수 및 주기 제공"]
    B --> C["시그널맵 (Signal Maps)
현시별 이동류(화살표) 번호·보행·황색 매핑"]
    C --> D["시뮬레이터 연산 엔진 (calc / simulation.js)
현재 주기 위치(pos)에 따른 등화(G/Y/R) 판정"]
    D --> E["화살표 및 신호등 DOM (junction_map.js)
방향별 화살표 실시간 녹색 점등 (#10b981)"]
STEP 1 시간계획 (TOD / Schedules)
현재 시뮬레이터 시각(t, 0~86399초)이 속한 시간대 슬롯을 탐색하여 운영할 플랜 번호(pIdx)를 결정합니다.
⬇
STEP 2 일계획 (Day Plans / Splits)
오늘 요일(평일/토/일)과 주간계획에 따라 해당 플랜의 현시별 스플릿 초수(splitA, splitB)와 총 주기(Cycle)를 산출합니다.
🛡️ 빈 일계획 자동 우회: 주말 플랜이 비어있으면 1번 평일 일계획으로 자동 우회
⬇
STEP 3 시그널맵 (Signal Maps)
각 현시가 진행될 때 실제로 점등해야 할 방향별 차량 이동류 ID(movA, movB), 보행 신호(pedMov), 황색 및 전적색 시간을 결합합니다.
🛡️ 불완전 맵 안전 폴백: 1현시만 있거나 황색시간 누락 시 0번 기본 일반맵으로 자동 우회
⬇
STEP 4 시뮬레이터 연산 엔진 (calc / simulation.js)
주기 내 경과 시간(pos = (t + offset) % Cycle)을 계산하여 현재 현시에 해당하는 이동류에 녹색('G') 또는 황색('Y') 신호를 부여하고 잔여 시간을 산출합니다. 연속 동일 이동류는 신호 단절 없이 녹색을 유지(Signal Merging)합니다.
⬇
STEP 5 화살표 및 신호등 DOM (junction_map.js)
모든 차량 이동류(1~16)와 보행자 신호(pedSet)를 식별하여 지도 상의 SVG 화살표 및 신호등 DOM을 실시간 녹색(#10b981), 황색(#f59e0b), 적색(#ef4444)으로 즉시 전환합니다.

2. 특수기능 예약계획 (시차제어 / 점멸 / 소등)

경찰청 교통신호기 설치운영 업무편람 기준에 따라, 특정 날짜 및 시간에 특수기능을 강제로 운영하는 예약 시스템입니다. 바이트(DATA 필드) 규격의 HIGH NIBBLE / LOW NIBBLE 처리 방식을 완벽히 준수합니다.

조건 설정 (날짜/요일) 우선순위

조건 설정 상태 제어 수행 방식
날짜(월/일) 지정 O, 요일 '0' (무관) 요일에 관계없이 지정된 해당 날짜의 시간에 제어 수행
날짜(월/일) 지정 X, 요일 '0' (무관) 해당 시간대에 매일 무조건 수행
날짜(월/일) 지정 X, 요일 지정 O 날짜에 상관없이 해당 요일의 시간에 제어 수행
날짜(월/일) 지정 O, 요일 지정 O 해당 날짜와 요일이 모두 일치하는 날의 시간에 제어 수행

NIBBLE 매핑 (기능 및 시차플랜)

예약 테이블의 기능(LOW)과 시차플랜(HIGH)은 실제 제어기 8번 바이트의 NIBBLE 값을 직관적으로 매핑한 것입니다.

  • 기능 (LOW NIBBLE): 예약 시 어떤 특수기능을 수행할지 지시합니다.
    1: 조광제어, 2: 점멸제어, 3: 소등제어, 4: 시차제어, 5: 감응제어, 6: 보행활성, 7: 음향발생
  • 시차플랜 (HIGH NIBBLE): 기능 값이 4 (시차제어)일 때만 활성화되며, 강제로 운영될 시차제 일계획 플랜 번호(6~10)를 지시합니다. 0을 입력하면 기본적으로 6번 플랜이 지정됩니다.
* 예시: 기능(LOW)을 '4'로 설정하고 시차플랜(HIGH)을 '7'로 설정하면, 해당 시간대에 주간계획을 무시하고 강제로 '7번 일계획'으로 동작합니다. 이후 시간계획(TOD)과 시그널맵 매핑은 7번 일계획에 등록된 데이터를 자연스럽게 따라갑니다.

3. 신호 시뮬레이터 등화 결정 우선순위

시뮬레이터는 교차로의 여러 설정(주간계획, 특수기능, 점멸 등)이 겹칠 경우 다음의 엄격한 우선순위에 따라 최종 표출될 시그널맵을 결정합니다.

  • 1순위
    특수기능 (점멸/소등) 예약
    예약계획의 기능이 2(점멸) 또는 3(소등)으로 설정된 시간이면, 다른 모든 계획을 무시하고 무조건 교차로를 점멸(황색/적색) 또는 소등 상태로 전환합니다. (통상 점멸 스케줄 기능도 이에 포함됩니다.)
  • 2순위
    특수기능 (시차제) 예약
    예약계획의 기능이 4(시차제어)로 설정된 시간이면, 주간계획(요일)을 무시하고 시차플랜(HIGH NIBBLE, 6~10번)으로 지정된 일계획(Day Plan)을 최우선으로 강제 적용합니다.
  • 3순위
    주간계획 (Weekly Plan)
    예약계획이 없는 일반 시간대에는 교차로에 설정된 주간계획표(월~일)에 따라 현재 요일에 맞는 기본 일계획(1~10번)을 선택합니다.
  • 4순위
    시간계획 (TOD Schedule)
    선택된 일계획(Day Plan) 내에서, 현재 시간에 해당하는 시간계획 플랜(1~16번)을 탐색하여 활성화합니다.
  • 5순위
    시그널맵 자동 우회 (Fallback)
    최종 결정된 시간계획에 매핑된 시그널맵(1~6번)을 불러옵니다. 단, 해당 시그널맵이 비어있거나 화살표 데이터가 그려져 있지 않은 경우, 시뮬레이터는 시스템 안정성을 위해 무조건 1번 일반 시그널맵(플랜1)으로 우회(Fallback)하여 표출합니다.

5. UTIC 신호데이터 TOD 일계획 · 시간계획 배치 표준 규격

SIGMA는 도시교통정보센터(UTIC) 원천 신호데이터를 수집하여 NO 1~6 주기별 3패턴 구조(하단 시간계획)와 24시간 시계열 운영 스케줄(상단 일계획)로 표준 정제하여 자동 매핑합니다.

(1) 하단 시간계획 : NO 1~6 및 INDEX 1~16 슬롯 배치 규칙

  • NO 및 INDEX 구성: 시간계획은 총 6개의 NO 그룹과 총 16개의 INDEX 슬롯으로 구성됩니다.
    • NO 1 : 1개 슬롯 (INDEX 1) — 기본 기저 주기
    • NO 2 : 3개 슬롯 (INDEX 2, 3, 4)
    • NO 3 : 3개 슬롯 (INDEX 5, 6, 7)
    • NO 4 : 3개 슬롯 (INDEX 8, 9, 10)
    • NO 5 : 3개 슬롯 (INDEX 11, 12, 13)
    • NO 6 : 3개 슬롯 (INDEX 14, 15, 16)
  • 동일 주기 배치 원칙: 하나의 NO 그룹에는 반드시 동일한 주기(Cycle)만 배치되며, 서로 다른 주기는 절대로 동일한 NO에 공존할 수 없습니다.
  • 주기 오름차순 및 빈칸 유지: UTIC 원천 데이터에서 주기가 낮고 시작시간이 빠른 순으로 NO 1부터 배치하며, 동일 주기가 3개가 되지 않더라도 빈칸으로 두고 주기가 변경되면 무조건 다음 NO 그룹으로 이동합니다.
  • 실시간 신호 자동화 연계 목적: 본 아키텍처는 도심 교통 정체 시 신호주기를 단계별로 상향하고, 상향된 각 주기(NO) 내에 유입(Inbound), 균형(Balance), 유출(Outbound)의 3가지 연동 패턴을 체계적으로 배치하기 위한 교통공학 표준 구조이며, 사용자가 직접 수동 입력할 때의 충돌을 방지합니다.

(2) 상단 일계획(TOD 계획정보) : 24시간 시계열 스케줄링

  • 시간 순서 정렬: 상단 일계획 테이블(#1~#16)은 하루 24시간(00:00~23:59) 동안의 신호 운영 흐름을 나타내며, 시작 시각(오전 ➔ 오후 ➔ 야간) 오름차순으로 슬롯 #1부터 차례대로 빈틈없이 배치됩니다.
  • INDEX 참조 연동 (IDX 필드): 상단 일계획의 IDX 값은 하단 시간계획에서 배치된 해당 INDEX 번호(1~16)를 참조하여, 특정 시간대에 정확한 스플릿 및 주기 패턴을 호출하도록 연결됩니다.

6. UTIC 데이터 수집 및 갱신 아키텍처 (시그마 API 기반 고속 동기화)

SIGMA 시뮬레이터는 안정적인 관제와 즉각적인 데이터 서빙을 위해 경찰청 UTIC OpenAPI 직접 호출 방식을 지양하고, 시그마 API(클라우드 DB) 중앙 허브를 통해 데이터를 동기화합니다.

구분 경찰청 UTIC OpenAPI 직접 호출 방식 SIGMA API 중앙 정제 허브 방식 (현재 표준)
응답 속도 교차로당 2~5초 소요 (전국 수천 개 동기화 시 수 시간 소요) 초당 50ms 이내 초고속 반환 (Supabase 인덱스 캐시)
데이터 완전성 주현시(Main Phase) 미포함, 결측 및 포맷 불일치 빈번 지자체별 주현시 사전 등록 및 NO/INDEX 표준 규격 완벽 정제
수집/조회 주체 시뮬레이터 브라우저 클라이언트 SIGMA SIM은 시그마 API(Supabase)로부터 즉시 로드
원천 데이터 최신화 클라이언트 개별 호출에 의존 시그마 API 백엔드(서버/DB 센터)에서 중앙 일괄 최신화 수행
📌 핵심 운영 지침:
• 시뮬레이터 관제/분석 시: 경찰청 API를 다시 조회하지 않으며, 이미 검증·정제되어 클라우드에 적재된 시그마 API의 데이터를 활용합니다.
• 데이터 최신화(갱신) 필요 시: 클라이언트가 아닌 시그마 API 서버(DB 센터 동기화 엔진)에서 경찰청 원천 데이터를 최신으로 갱신해야 하며, 갱신된 최신 데이터는 시그마 클라우드 DB를 통해 전국 모든 사용자에게 즉시 전파됩니다.
