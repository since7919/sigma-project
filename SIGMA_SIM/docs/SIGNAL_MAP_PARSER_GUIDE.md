# 엑셀 시그널맵 파싱 규칙 및 과거 문제 해결 이력 (SIGNAL MAP PARSER GUIDE)

이 문서는 `data_parser.js`에서 엑셀(Excel) 파일의 **시그널맵(Signal Map)** 영역을 파싱할 때 반드시 지켜야 할 **절대 규칙**과 과거 발생했던 치명적인 버그 및 해결 이력을 기록한 것입니다.
**AI 에이전트가 코드를 수정할 때, 이 문서를 반드시 읽고 동일한 실수를 반복하지 않도록 주의해야 합니다.**

---

## 🛑 1. 절대 규칙: 동적 탐색(Dynamic Detection) 금지
엑셀의 서식 변경을 대비한다는 명목으로 `MIN`, `LSU1`, `EOP` 등의 헤더 텍스트를 `includes`나 `===`로 **동적으로 찾는 로직(findCol 등)을 절대 추가하지 마십시오.**

* **행(Row) 위치는 항상 고정입니다:** 시작 행(`baseRowMapStart`)은 무조건 **247** 입니다.
* **열(Column) 위치는 항상 고정입니다:** 
  * `MIN`: 53열
  * `MAX`: 55열
  * `EOP`: 57열
  * `LSU V/P`: V는 `5 + lsu*6`, P는 `8 + lsu*6`
* **이동류(Movement ID) 행:** 무조건 **Row 5**와 **Row 12** 입니다.

### ⚠️ 왜 동적 탐색을 하면 안 되는가? (과거 버그 이력)
1. **False Positive 버그 ("ADMIN" 사태):** `.includes('MIN')`으로 열을 찾게 구현했더니, 엉뚱하게 "ADMIN"이라는 단어가 포함된 열을 MIN으로 착각하여 데이터를 엉망으로 가져오는 문제가 있었습니다.
2. **헤더 유실 버그 (병합/숨김 열 사태):** 정확한 일치(`=== 'MIN'`)로 헤더를 찾게 했음에도 문제가 발생했습니다. 에이전시에서 엑셀을 작성할 때 **열을 숨기거나(Hidden) 셀을 병합(Merged)** 하는 경우가 많아, 파서 입장에서는 해당 행에 "MIN"이나 "EOP"라는 텍스트 자체가 사라진 것으로 보입니다. 이로 인해 헤더 찾기에 실패하고, 엉뚱한 아랫줄(예: 281행)을 시그널맵 시작점으로 잡아버려 모든 데이터가 `00`으로 표출되는 대참사가 발생했습니다.

---

## ✅ 2. 해결책: 병합/숨김 열 대응 추출 로직 (`getSafeVal`)
위치(인덱스)는 하드코딩으로 고정하되, **병합되거나 숨겨진 열 때문에 사용자가 실제 값을 입력한 물리적 칸이 1~2칸 밀릴 수 있는 현상**을 방어해야 합니다.

* 엑셀에서 BA열(53)과 BB열(54)이 병합된 경우, 값은 53에 들어갑니다.
* 하지만 병합이 풀리거나 숨겨진 열이 개입되면, 사용자가 53 대신 54에 값을 입력할 수도 있습니다.
* 따라서 값을 가져올 때는 무조건 **기준 열(`c`)과 그 인접 열(`c+1`)을 함께 검사하여 존재하는 값을 추출**해야 합니다.

### 코드 적용 방식 (`getSafeVal`)
```javascript
// data_parser.js 내부에 적용된 안전 추출 함수
const getSafeVal = (r, cStart, cEnd) => {
    for (let c = cStart; c <= cEnd; c++) {
        const v = getVal(r, c);
        if (v !== null && String(v).trim() !== "") return v;
    }
    return "";
};

// 사용 예시 (반드시 인접 컬럼까지 탐색 범위를 줍니다)
const minStr = String(getSafeVal(r, minCol, minCol + 1)).trim();
const eopStr = String(getSafeVal(eopRow, eopCol, eopCol + 1)).toUpperCase().trim();
```

## 📝 3. AI 에이전트 행동 지침
만약 사용자가 **"시그널맵이 00으로 나온다"** 거나 **"엑셀 로딩이 빈칸이다"** 라고 문제를 리포트한다면:
1. `data_parser.js`에 누군가 실수로 **동적 탐색(헤더 글자 찾기) 로직을 부활시켰는지** 확인하고 즉각 폐기하십시오.
2. 하드코딩된 인덱스(`baseRowMapStart = 247`, `minCol = 53` 등)가 변경되었는지 확인하십시오.
3. `getVal(r, c)`를 단일 칸만 조회하도록 바꾼 곳이 있는지 확인하고, 반드시 `getSafeVal(r, c, c+1)`로 2칸 이상을 스와이프 하도록 복구하십시오.
4. 이 모든 것이 정상이라면, 파서의 문제가 아니라 **해당 엑셀 파일의 시그널맵 영역이 실제로 비어있는 것**입니다. (사용자에게 엑셀 파일의 데이터 유무를 확인하도록 안내하십시오.)
